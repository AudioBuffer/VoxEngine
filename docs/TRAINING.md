# VoxEngine 模型训练方案

## 0. 在哪训（重要）

**这台手机训不了。** 实测：无 `numpy / scipy / librosa / torch / onnx`，
Python 3.14 基本没有 torch wheel，只有 `ffmpeg`。

| 环节 | 在哪做 |
|---|---|
| 数据准备 / 提取音高 / 训练 / 导出 ONNX / 量化 | **PC 或 Colab**（装 PyTorch + librosa + onnx） |
| **验证模型能不能被引擎加载并推理** | **这台手机**：`tools/onnx_check.cpp`（用随包 onnxruntime，不需要 Python） |

## 1. 先训哪个

| 顺序 | 模型 | 为什么 | 难度 |
|---|---|---|---|
| **①** | `speech_f0.onnx` / `singing_f0.onnx` | 标签好做（音高提取是成熟问题）、公开数据多、输出维度小、训好立刻能用（哼唱→F0→驱动引擎） | 低 |
| ② | `polish.onnx` | 感知提升最大，但需要成对对齐数据 | 中 |

**建议先训 ①**，跑通"训练→导出→本机验证"整条链路，再上 ②。

## 2. 数据

- 格式：**44100 Hz 单声道** WAV，幅度 [-1, 1]
- 推荐公开集（都带音高标注或易提取）：
  - **MIR-1K**（卡拉OK，含 F0 标注，中文流行歌，起步最合适）
  - **MDB-stem-synth**（人声分离 stem，带 F0）
  - **Vocadito**（清唱，带 F0）
  - **NUS-48E**（48 首英文歌，有音高标注）
  - 自己的录音最好（同一人、同一套发声习惯，最终效果最贴合）

## 3. 提取音高（关键步骤）

**参数必须和引擎一致**，否则训出来的 F0 与引擎分析对不上：

| 参数 | 值 |
|---|---|
| 采样率 | 44100 |
| 帧长 | 1323 样本（30 ms） |
| 帧移 | 661 样本（15 ms） |
| 搜索范围 | 80 ~ 800 Hz（男声）/ 100 ~ 1000 Hz（女声） |
| 输出 | Hz + 清浊标记（unvoiced 用 0） |

工具任选：`librosa.pyin` / `torchcrepe`（CREPE，精度高）/ `torchaudio` / RMVPE。
**必须做后处理**（不做会有倍频/半频误判，听起来就是"乱跑调"）：
1. 5 点中值滤波去掉孤立跳变
2. 半频/倍频纠正：若 `lag/2` 或 `lag/3` 处自相关峰 ≥ 0.85×最佳峰，取那个
3. ≤3 帧的短空隙线性插值填平

> 这三步和引擎内 `computePitch()` 的做法一致，别自己另搞一套。

## 4. 按契约切块

- **固定 16384 样本一块**，滑窗步进 **8192**（50% 重叠）
- 引擎运行时自己做重叠相加 + 三角窗交叉淡化，**你训练时不用管块边界连续性**
- F0 标签：块内 **T = 23 帧**，第 i 帧 = 样本区间 `[661*i, 661*i + 1323)`（i = 0..22）
  （23 × 661 + 1323 = 15865 ≤ 16384，无需补零）

## 5. 训练与导出

- 网络：小型 1D-CNN / UNet，**1~3M 参数**足够（这是后处理，不是声码器）
- F0 损失：清浊掩码下的 L1（浊音）+ 二元交叉熵（清浊）
- polish 损失：L1 + **多分辨率 STFT 损失**（单用 L1 会糊）
- 导出 ONNX：**opset 13**，float32，**固定 shape**（不要动态轴）
- 量化：动态量化到 **Q8**，和需求 006 一致

## 6. 成对数据怎么造（polish 专用）

利用"引擎可被 F0 驱动"这一点：

```
真人清唱 WAV
   → 提取 F0 + 音素时长
   → 用该 F0/时长驱动 VoxEngine 合成   ← 得到【输入】
   → 原录音本身就是【目标】
   → 两者逐帧对齐，直接成对
```

单条录音就能产出成千上万个 16384 样本的块。

## 7. 本机验证（必做，别跳过）

```bash
cd ~/Desktop/dsh/VoxEngine
clang++ -O2 -std=c++17 -DVOX_WITH_ONNX -Isrc -I$HOME/onnxdev/headers \
  -o /tmp/t_onnx tools/onnx_check.cpp \

  -Wl,-rpath,$HOME/onnxdev/jni/arm64-v8a -lm
/tmp/t_onnx 你的模型.onnx
```

它会真的加载 + 真的推理，并校验张量能不能取到。**通过了才装 app。**

## 8. 最常见的三个坑

1. **张量名写错** → 能加载但取不到张量。必须叫 `pcm_in` / `pcm_out` / `f0`
2. **动态 shape** → 引擎按模型输入最后一维决定分块长度，动态维会回退 16384，
   你若按别的长度训练就会形状不符
3. **采样率不是 44100** → 训练时若重采样过，推理时音高会整体偏移（比如 16k 训练的模型喂 44.1k，F0 会差 2.75 倍）
