# VoxEngine ONNX 模型契约 v1（0.6.0-alpha 起生效）

> 已用真实模型在本机（aarch64-android / ONNX Runtime 1.19.2 C API）**实测通过**：
> 加载成功、推理成功、输出与预期逐样本一致（最大误差 2.98e-08 = float32 精度极限）。
> 训练必须严格对齐本契约，否则运行时会"能加载但取不到张量/形状不符"。

## 通用约定
| 项 | 约定 |
|---|---|
| 采样率 | 44100 Hz |
| 声道 | 单声道（shape 里固定为 1） |
| 数据类型 | float32（ONNX elem_type = 1） |
| 数值范围 | [-1, 1]，引擎不做额外归一化 |
| 量化 | Q8（动态量化），与需求 006 一致 |
| 张量名 | **必须严格一致**，见下 |
| 批大小 | 固定 1 |

## 1. polish.onnx —— 波形润色（主用）
| 项 | 值 |
|---|---|
| 输入名 | `pcm_in` |
| 输入形状 | `[1, 1, N]`　N 由模型自身决定；**推荐 N = 16384**（引擎会从模型读最后一维，动态维则回退 16384） |
| 输出名 | `pcm_out` |
| 输出形状 | `[1, 1, N]`（与输入同长） |

引擎侧行为：**50% 重叠分块 + 三角窗交叉淡化**，所以模型只需保证单块内是"整块进、整块出"的映射，块边界由引擎处理，**训练时不必考虑边界连续性**。

## 2. speech_f0.onnx / singing_f0.onnx —— 基频预测
| 项 | 值 |
|---|---|
| 输入名 | `pcm_in` |
| 输入形状 | `[1, 1, N]`　推荐 N = 16384 |
| 输出名 | `f0` |
| 输出形状 | `[1, T, 1]`，float32，单位 Hz（清浊用 0 表示 unvoiced） |
| **T 必须 = 23** | 对应输入 16384 样本；第 i 帧 = 样本区间 `[661*i, 661*i+1323)`，i = 0..22 |
| 帧长 / 帧移 | 1323 样本（30 ms）/ 661 样本（15 ms） |

## 自检命令
模型训好后，先跑本机校验（不需要装 app、不需要开界面）：

```bash
cd ~/Desktop/dsh/VoxEngine
clang++ -O2 -std=c++17 -DVOX_WITH_ONNX -Isrc -I$HOME/onnxdev/headers \
  -o /tmp/t_onnx tools/onnx_check.cpp \
  -L$HOME/onnxdev/jni/arm64-v8a -lonnxruntime \
  -Wl,-rpath,$HOME/onnxdev/jni/arm64-v8a -lm
/tmp/t_onnx 你的模型.onnx
```

## 降级保证
接口内没有模型 / 加载失败 / 未编译 ONNX 支持时：
`ready()` 恒为 `false`，所有调用是**零副作用空操作**，引擎走**纯参数（DSP）合成**，
不等待、不报错、不产生半截输出。此路径已在 `--selftest` 中覆盖。
